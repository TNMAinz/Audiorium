# Feature status

Status vocabulary: **implemented and verified**, **implemented, not verified**,
**partially implemented**, **blocked**, **planned**. "Verified" means a test or a
gate exercises it and the result was observed, not that the code looks right.

Evidence at the time of writing: `cargo test` 235 passed, 8 ignored, `npx vitest
run` 461 passed in 45 files, `npx tsc --noEmit` clean, `npm run build` clean, and
the delivery gate (`.unlazy/verify-delivery.mjs`) plus `.unlazy/fit-spec.mjs`
green against the running Windows build. The patch store was also verified across
a real restart of the app process, not only across a page reload, and the
observatory through the running build (readings, hover naming, press-to-open and
fit at eight sizes).

| Look-ahead true-peak limiter | Implemented and verified | The detector judges a frame by the peak of a 4× oversampled interpolation (the same windowed-sinc branches the meter measures dBTP with), so an inter-sample crest is reduced instead of being clipped flat after encoding. `limiter.rs` tests hold a loud sine at the threshold, hold a 12 kHz tone at 45° — whose samples read -3 dBFS while its waveform peaks at full scale — under a -3 dBTP ceiling at -2.9 dBTP with the samples pulled to about -6 dBFS, and still report the ceiling as the output level at two different ceilings. | Equaliser in the real path | Implemented and verified | Chain order test: an 18 dB EQ boost followed by a -6 dB limiter still peaks at -5.9 dBFS; `eq_enabled` reported in the meter payload |
| Dynamic bands: a band gives way when its own region is loud | Implemented and verified | `eq::Dynamics` adds threshold, ratio, attack and release to one band. The detector is the band's own biquad output, so a loud kick does not duck the treble; the share of the band that survives is slewed by a fixed per-sample step so a change cannot click. A static band is unchanged and an older settings file loads static (`EqFilter::dynamics` is optional with a default). `validate` refuses a threshold outside −60…0 dBFS, a ratio outside 1:1…20:1, an attack outside 0.5…200 ms and a release outside 10…2 000 ms. `eq::tests::a_dynamic_band_gives_way_when_its_own_region_is_loud`: a 12 dB band on a quiet tone measures its 12 dB within 1 dB, the same band on a loud tone keeps under 4 dB, and the static band still measures 12 dB when loud. The Equaliser's `Dynamic` switch writes it through `set_eq`; verified in the shipped build by reading `{"thresholdDb":-24,"ratio":3,"attackMs":10,"releaseMs":200}` back from the engine |
| Rack on the sum and the difference | Implemented and verified | `StereoMode::Ms` encodes to mid/side around the rack and decodes back, and only while the rack is doing something, so a bypassed rack in mid/side stays bit-exact. `chain.rs` tests: encode and decode are inverses, an idle rack in mid/side is bit-exact, and the switch runs the rack on the sum and the difference. The `Channels` bank on the Processors page is asserted by `ProcessorRack.test.tsx`; the shipped build switched to `ms`, read it back from `chain_config`, and was left in `lr` |
| Clicks avoided on change | Implemented and verified | `eq.rs` test measures the largest sample step through a 12 dB change against the settled signal; the change is crossfaded over 10 ms |
| Filter response curve | Implemented and verified | `eq_response` computes from the running coefficients at 160 points; the plot renders that array only |
| Compressor: threshold, ratio, knee, attack, release, make-up | Implemented and verified | `compressor.rs` tests: a signal below the threshold is untouched, a 4:1 ratio compares its reduction against the curve it should follow, make-up restores the level the reduction took, the detector is stereo-linked, bypass is bit-exact and clears the tail. Not multiband and not a limiter |
| Saturator: oversampled tanh, tone, mix | Implemented and verified | `saturator.rs` tests: drive adds harmonics that stay below the band at 4× oversampling, a 6.5 kHz tone produces no aliased image below it, `mix = 0` and bypass are bit-exact, the DC blocker removes the offset the curve lifts, `tone` tilts without changing the level |
| Rack order chosen by the user, with the file's stages honoured | Implemented and verified | `ChainConfig` carries an `order` list; `ChainConfig::validate` rejects a list that repeats a stage or leaves one out, and `Chain::process_rack` runs it. `chain.rs` tests: the default order is the historical one, a reordered rack gives a different result than the default one for a non-commuting pair, and a settings file written without an `order` loads with the default |
| Chain persistence: panner, reverb, equaliser, compressor, saturator, limiter and the order | Implemented and verified | One JSON file in `%APPDATA%\AUDIORIUM`, written whole by rename on a coalescing thread; `store.rs` round-trip and coalescing tests, `chain.rs` restart test, and gate F8 reads the file while the app runs |
| Saved equaliser patches, with shipped patches that cannot be overwritten | Implemented and verified | Editing a shipped patch saves a copy in the engine (`presets.rs`), keeps the original untouched, and the copy can be renamed and deleted; `presets.rs` and `chain.rs` tests, gate F8 through the interface, and a real process restart |
| Patch per headphone / per device, patch export and import | Not implemented | The store holds one library of patches; nothing maps a patch to a device, and no file format is offered for exchange |
| Convolution, VST, loudness normalisation | Not implemented | Not present, not claimed |

## Analysis and metering

| Feature | Status | Evidence / limit |
| --- | --- | --- |
| Real-time spectrum, 56 bands, 2048-pt Hann FFT | Implemented and verified | `analysis.rs` computes it from the frames the player wrote to the device; gate F9 plays a 1 kHz tone and finds it at 1026 Hz |

The frontend also holds a level it has just sent until the engine reports the same one, so a poll that left before the drag cannot pull the thumb back under the pointer |
| Playback level remembered between launches | Implemented and verified | The engine's level is memory-only, so every launch played at 0.7 however often it was moved. The interface now keeps it with the other settings in the WebView's own storage (`audiorium.playback-level`): `usePlayer` starts at the remembered level, hands it to `set_playback_volume` once before a track opens, and writes it on every change, so the engine and the slider agree and the poll cannot pull the thumb back. Verified in the running 1.0.6 build: the level was pressed down to 0.52 (52 % · −5.7 dB) in the setup dialog, the app was quit and started again, and the new process reported `playback_status.volume` 0.52 with the slider drawn at 52 % before anything was touched |

A capture played back into the output it reads is refused with the reason shown, and the capture keeps metering. The capture thread only queues frames; the monitor's own thread owns the render stream, keeps the device fed, fills with silence instead of replaying stale frames and fades the first 10 ms in, so a late packet is a gap rather than the clicks and bursts of static the first version produced (it wrote only the space the device reported and dropped the rest of each packet). Read on the Master page's before/after table, not on the live meters |
| True peak (dBTP) | Implemented and verified | 4× oversampled windowed-sinc interpolation rather than sample peak, in the same `loudness.rs` meter; a test pins a signal whose inter-sample peaks exceed its samples and checks the oversampled figure is the higher one. | Offline analysis of a chosen file | Implemented and verified | The Master page renders a library file through the rack on its own thread and meters it twice, before and after, so the table is the file's own numbers rather than what happens to be playing. A render that fails or is cancelled removes its partial output and reports why |
| Three export rates, converted after the rack | Implemented and verified | `export::SampleRate` offers 44.1, 48 and 96 kHz and `render.rs` converts after the processors with a 32-tap windowed-sinc `Resampler` whose cutoff follows the lower rate, so 48→44.1 band-limits before decimating and a constant signal stays constant. The Master page's switch is asserted by `pages.test.tsx` and the header names the rate; `render::tests::a_master_can_be_written_at_441_and_96` reads both files' headers back. The shipped build wrote a 44.1 kHz 24-bit master |
| An album mastered as one programme | Implemented and verified | `render_album` writes tracks that share an artist and album, in library order, through the rack as it stands, reporting `trackIndex`/`trackTotal`; `albumLufs` is gated integrated loudness over every track's 400 ms blocks concatenated, not an average of the tracks' figures. `render::tests::an_album_is_written_in_order_and_judged_as_one_programme`; `pages.test.tsx` asserts the card appears for two tracks on one album and never for a single track. The shipped build wrote three tracks and reported album loudness −15.40 LUFS |
| Reference measurement and comparison | Implemented and verified | `reference_measure` decodes the chosen file through the same `Loudness` meter a render uses, writing nothing and running no stage. The page names it, states the distance (`Reference −14.7 LUFS · master −16.1 LUFS · −1.5 LU apart`) and offers the reference as a side of the level-matched A/B. `render::tests::a_reference_is_measured_with_the_same_meter_a_master_is`; the shipped build read a real reference and listed `Reference` among the comparison's sides |
| The render path is proven transparent | Implemented and verified | `null_test` decodes a file, runs it through `Chain::process_rack` with every stage bypassed and compares it with the source sample by sample, reporting frames, differing samples and the worst difference in dB. `render::tests::a_bypassed_rack_returns_the_samples_it_was_given`; the page's `Bypass test` printed `Identical · 9 215 997 frames` in the shipped build |
| Delivery target on the master | Implemented and verified | `masterSpec.ts` holds the figures a delivery expects — streaming -14 LUFS, podcast -16, EBU R128 broadcast -23, each with a -1 dBTP ceiling — and reports the distance the rendered master is from the chosen one instead of re-rendering to fit: a loudness within ±0.5 LU holds, a true peak over the ceiling does not, and the gain that would close the gap is stated rather than applied. "None" judges nothing, so a file cannot fail a spec it was not given, and before a render there is no verdict at all rather than a pass over a dash. Seven unit tests cover meeting, loud, quiet, over-ceiling, None and unmeasured, and the page test reads `2.3 LU loud` with `Moving the master −2.3 dB would land on −14.0 LUFS`
| Level-matched A/B of source and master | Implemented and verified | The comparison plays either the source or the master with `set_monitor_trim`, a monitor gain carried beside the user's level in `PlayerState` and applied in both output loops, and with `set_monitor_direct` bypassing the rack — a master already contains the rack, so hearing it through the rack again would judge a twice-processed file against a once-processed one. The page pulls the louder side down by the difference the render measured, never up, and resets both when the page is left or a new master is rendered. The fader is untouched, so a comparison cannot leave the level changed. `player.rs` tests the trim's range and that it only attenuates (0 dB → 1.0, -6 dB → 0.501, +0.5 dB refused)
| The master carries the source's title, artist, album and cover | Implemented and verified | `export.rs` writes a `LIST`/`INFO` chunk (`INAM`, `IART`, `IPRD`, `ISFT`) and, when the source had a picture, an `id3 ` chunk with a front-cover `APIC` frame; the bytes come from the source file itself (`library::tags_of`, `artwork::original_cover`), not from the page. `library.rs` reads both chunks back, so a scanned master shows its own title. Tests: the export test reads the chunks out of the written file, the library test reads a WAV's INFO and nested ID3 back, and the render test renders a tagged source and then asserts the master's tags, its byte-identical cover, that the cover still draws through `artwork::load`, and that `player::decode` still reads 48 000 frames past the new chunks |
| Render a mastered file to disk | Implemented and verified | `render.rs` decodes with the same Symphonia path playback uses, runs `Chain::process_rack`, and `export.rs` writes 48 kHz stereo WAV — 16/24-bit with TPDF dither, 32-bit float without — or a lossless FLAC of the same samples. At 16 bits the dither is noise-shaped per channel: the quantiser's own error is subtracted from the next sample before rounding, so the noise heard is a first-order high-passed version of the floor. The export test renders the same tone twice and measures the error below about 500 Hz at under a quarter of the flat dither's power while the total error power rises — the noise was moved, not removed — asserts no sample lands more than four codes from the signal, and checks two renders of one file are byte-identical. The tail runs on past the last frame by the room's decay plus the look-ahead so nothing is cut. The output is a new file named `(mastered)` in a `Mastered` folder at the library root (or beside a source from outside the library) and the source is never written; the scan leaves that folder out, so a master is never listed or mastered again. The FLAC writer codes one 4096-sample frame at a time and patches `STREAMINFO` with the frame count, block/frame sizes and the sample MD5 when the stream ends; the container chooses the extension. Tests: the render test renders the same source to both containers and asserts the FLAC is smaller, carries the same tags and a byte-identical cover, and decodes through `player::decode` |

## What to do next, in order

1. Headphone Lab, the remaining half: the AutoEq-compatible parser, the
   provenance (label, file, terms), the preamp and the response graph all exist and
   ship with sixteen vendored corrections. What is missing is a file picker for a
   profile the user brings, so an arbitrary model can be added without a build, and
   a licence review of that third-party data.
2. Test bench: sine, sweep, pink/white noise through the real path, at a
   conservative default level with a visible stop.
3. Blind listening lab: ABX over two processing configurations, level-matched,
   with an honest binomial result.
4. Patch exchange: export and import of a patch as a JSON file, so a correction
   can leave this machine.
5. Loudness normalisation against a target, now that the meter can say what a
   file measures: the render has the numbers but nothing writes them back.
6. More export formats: Opus, and a FLAC at 32-bit float (the format has no float
   sample), neither of which the current encoder can produce.
